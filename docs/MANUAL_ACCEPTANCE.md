# 五台手机手动验收

状态：2026-10-28，1.2.3+64 设备验收清单。自动化通过不代表这些真机项目已通过；尤其不能据此宣称跨平台 Aware 无线已验证。

## 准备

1. 五台设备安装同一批待验收构建。安卓使用签名 APK，或从 Google Play 内部测试安装由 AAB 分发的版本；AAB 不能像 APK 一样直接点开安装。iPhone 使用签名的开发包或 TestFlight，未签名的编译产物不能直接安装。
2. 在“关于”中记录完整版本号和构建号。新版近场 v3 房间要求所有成员升级，不能用旧版混测来判断新版失效。公网房仍单独回归。
3. 系统设置中记录实际系统版本与厂商系统版本，不凭手机型号推断功能支持。
4. 先不开蓝牙耳机，允许麦克风、附近设备、蓝牙、局域网与通知权限。每轮先清空应用日志，再开启日志重现；分享前检查日志，隐藏昵称等个人信息。
5. 使用临时昵称和测试文本，不放真实私密内容。所有手机日期时间设为自动。

## 图标与启动

- 检查桌面、应用列表、系统应用信息、最近任务、应用内关于页；应为第一个方案：深蓝底、暖色太阳与三条声波。
- 安卓切换浅色/深色和系统主题图标；检查圆形、圆角方形裁切，前台通话通知的小图标应为相同轮廓。
- iOS 切换浅色/深色/着色图标，冷启动查看启动画面；检查是否闪出旧图。系统桌面可能缓存旧图，先重启手机再复测；不要为刷新图标直接清除安全存储。

## 原有功能回归

1. 五机连接同一 Wi-Fi 或热点，关闭移动数据并断开路由器外网，确认消息与语音不依赖互联网。
2. 建立 Wi-Fi 房，依次加入；名单、房名、昵称、人数应一致。双向发送文字、表情、长中文，互发图片。
3. 先按键通话，再测试自动语音/静音、扬声器、蓝牙耳机。每次结束对讲后手机不得继续采集；自动语音模式只在明确启用时采集。
4. 关闭一个成员的 Wi-Fi 约 30 秒再打开。应显示恢复过程，重新连接后文字可补齐；不得自动恢复“按键按住”。
5. 在支持交接的 Wi-Fi 房测试房主主动离开/转移，再让新房主接收新成员；重复一次房主直接断网。蓝牙房仍不支持房主转移，需结束后重新建房；分别记录各房型结果。
6. 单独开启移动数据测试公网房、融合房本地/云端切换。语音不应重复播放，退出房间后通知与麦克风指示应结束。

## GATT 文字备用通道

此项必须验证实际备用路径，不能只用一次正常蓝牙通话代替。

1. 两台打开飞行模式，再手动打开蓝牙，保持 Wi-Fi/移动数据关闭。房主创建蓝牙房。
2. 加入者先正常加入，打开房间设置 → 连接诊断 → “验证蓝牙文字备用通道”。打开该开关，退出房间再加入。
3. 加入者应显示“蓝牙备用连接 · 仅文字”；成员名单应显示“仅文字”。此时不应出现可用的对讲/图片发送入口，不应打开麦克风。
4. 双向各发 20 条带序号文字，等待确认；撤回其中一条。关闭加入者蓝牙 20 秒再打开，等待恢复并检查遗漏、重复与撤回复活。
5. 同一房间加入第三台正常 L2CAP 设备：两台正常设备继续对讲，文字备用设备仅收发文字，不能拖垮正在通话的链路。
6. 关闭验证开关，退出后重新加入。应优先恢复正常语音路径。强制结束并重开应用也会清除该测试开关。
7. 对 A↔C、B↔E 分别交换房主再做。系统后台若不再发现/连接，记录持续时间、前后台状态和权限；不要填写“已支持后台互通”。

## 文字补齐、撤回与成员身份

1. 三台入房并等待 10 秒。A/B 连续各发 10 条编号文字；让 C 临时断链，再继续发 10 条，恢复 C 后等待至多 2 分钟检查补齐。
2. C 断链时撤回 A 的一条消息，恢复后确认该消息不出现。再加入第四台，历史同步也不得恢复它。
3. “等待确认”不能当作已送达；所有预期接收者确认后才显示确认状态。记录无法补齐的具体编号与断链时间。
4. 两台设置相同昵称及三位编号（如可编辑），进入“成员安全号码”。同一成员在不同设备上的完整号码应一致，不同身份的号码应不同；不能因编号相同而获得撤回他人消息的权限。
5. 重启同一安装，安全号码应保持；清除安全存储/重新安装可能更换身份，需重新核对。
6. 成员离开后其余成员继续发文字和通话，新 epoch 应正常工作；离开者需重新入房。是否能抵抗抓包解密由自动化与专项安全测试验证，不能仅凭退出 UI 判断。

## 可选语音留言

1. 默认关闭：按键说话不应产生留言。
2. 房间设置开启“将我的按键通话保留为留言”。按住说 3 秒，再松开。双方应各只有一条留言，接收方不能自动播放。
3. 点击播放，再停止；快速连续切换播放/停止 20 次。随后实时对讲，留言应停止，不抢占实时通话。
4. 按住超过 15 秒：留言最多保存 15 秒，实时通话仍继续。正在留言时点取消，接收方的占位也应被撤回。
5. 接收方中途断链，恢复后等待补齐；不得出现“实时一条、补送又一条”。对已补齐留言撤回，再断链恢复，不得重新出现。
6. 使用系统闹钟/电话或切换音频设备打断播放，检查是否停止、界面是否恢复。退出房间不应继续播放；清理房间后临时留言不应成为后台录音。

## 离线转交：三机分时相遇

1. 先 A/B 同房，在首页或房间设置打开“离线转交”。核对安全号码后，A 在“记住房内联系人”保存 B。普通房间聊天不会自动进入此队列。
2. A、B、C 都主动开启转交。B 离开；A 给 B 写一条密封留言。界面显示已排队，不得显示“对方已收到”。
3. A/C 同房约 1 分钟。C 应出现托管记录，看不到正文。让 A 离开并关闭应用。
4. 强制结束并重开 C（不卸载），让 C/B 进入另一个新房间。等待约 1 分钟，B 应收到一条可读消息，内容一致；反复重连不增加重复记录。
5. 再让 A/C 相遇，A 撤回；随后 C/B 相遇。B 的记录应变为撤回，不再显示正文。已看过内容无法被“抹去”，不要将此项描述为远程擦除。
6. C 关闭转交后重复步骤，不能继续替人交换。重新开启可继续未到期队列；清空并关闭会删除本机联系人及队列。
7. 等待实际 24 小时后再次启动，消息应过期清理。勿只调整系统时间判定密码学到期；自动化另覆盖到期和时钟异常。
8. 压力项：填满 64 条后再写一条，应拒绝新条目并保留原有记录；不要静默挤掉未撤回消息。

## 锁屏与长时间通话

每组设备均测试前台 2 分钟、锁屏 5 分钟、切其他应用 5 分钟，并分别使用扬声器和蓝牙耳机。记录：声音是否连续、是否意外开麦、通知/锁屏控件是否可用、来电或失焦后是否正确暂停、解锁后是否需要恢复。

安卓先使用默认电池设置；失败后再单独测试允许后台运行，分别记录两组结果。iPhone XR 与 iPhone 17 Pro 不共用一份结果。测试完退出房间，确认系统麦克风指示、播放、前台通话通知均停止。

## Wi-Fi Aware 可选加速

1. 先通过现有 Wi-Fi/热点或服务器建立同一个融合房间。房间设置展开“可选 Wi-Fi Aware 加速”，两台都检查设备报告。此功能不代替首次入房。
2. Android 的标准配对数据通道使用 Android 17 / API 37 新接口，并检查 NAN 配对硬件与当前可用性；iOS 使用 iOS 26+ 的 WiFiAware 与系统配对，另需支持该能力的硬件和包含 Publish/Subscribe 权限的签名描述文件。不能只凭手机型号认定支持。
3. 房主和成员分别点“尝试启用”。iPhone 双方点“配对设备”，在系统界面完成选择和配对；Android 房主会显示配对码，Android 加入者输入对方显示的码后点“配对设备”。同平台成功后再测混合平台，并互换房主。
4. 等待状态显示“Wi-Fi Aware 加速已连接”。在正常对讲与文字过程中关闭原热点/移动数据，观察是否仍能通过加速链路通信。仅显示“已启用/等待配对”不能算通道已建立。
5. 关闭加速、取消配对、拒绝附近 Wi-Fi 权限、设备移出范围分别测试。原有房间不应被解散；保留的 LAN/云端链路应继续或按原重连规则恢复。新房主接任后需重新启用加速。
6. 对系统报告不支持的设备记录“不支持/已回退”。热点或 Wi-Fi Direct 可能占用同一无线资源；系统暂不可用时不要为追求加速强制断开正在使用的网络。
7. Apple 与 Android 的配对和数据通道虽然使用标准接口，仍受实际系统、芯片和固件实现影响。三组分别记录 Android↔Android、iOS↔iOS、Android↔iOS，不把其中一组成功替代其他组。无可支持的设备或未授权的签名包时，这项保持“未测”。

## 反馈格式

复制填写：`场景 / 房主设备 / 加入设备 / 系统版本 / 应用版本构建 / 是否有外网 / 耳机 / 前后台与锁屏时长 / 具体操作 / 预期 / 实际 / 时间点 / 日志文件`。

所有项目初始状态均为“未测”。仅在实际操作后标记通过、失败或不支持，并保留失败时的日志和时间点。
