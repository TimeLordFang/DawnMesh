# 1.1.0 Beta：直连融合与服务端动态能力

## 录音恢复

Android 监听耳机 HFP 连接广播和蓝牙输入设备变化，合并短时间内的路由变化。API 31+ 重新选择双向通信设备，并等待路由就绪（最多约 5 秒）；旧系统恢复 SCO。近场房停止旧 AudioRecord、唤醒阻塞的 read 后重建；公网房重新创建 LiveKit 本地音轨的采集并重新挂载降噪。不会以“长时间没说话”作为录音故障依据。

公网采集更新串行执行，录音恢复期间发生松开 PTT、静音或禁言时，以最新状态决定是否开启麦克风。静音/未按住 PTT 时只记录待恢复标记，在允许发言时处理。Android 机型及耳机固件仍会影响恢复效果，本版本没有真机距离断连验证。

## 双线融合（房主统一开启的实验功能）

需 Server 0.3.0-beta.2 或更新版本，所有 Android 成员建议升级到 1.1.0-beta.3。只有房主显示房间顶部的融合开关；房间偏好由服务端保存并广播，当前及后加入成员自动跟随，无需各自开启。房主建立 Wi-Fi Direct 群组并确认就绪后，通过公网加密信令发送群组信息；成员自动连接与重试。群组凭据由随机房间密钥与房主身份派生，转让房主后自动重建。已有局域网/P2P 网络也可用于直连，对进程重启或旧版底层重试留下的群组，仅在 SSID 精确匹配当前房间派生值时接管并广播；不拆除其他群组。不会把整个进程绑定到 P2P 网络。

- 共享 LiveKit 的本地麦克风音轨与降噪，仅采集一次；每个参与者最多额外连接 4 位同伴。
- Android 在首次创建 WebRTC 连接前接入受权限保护的 Wi-Fi Direct 网卡监听，沿用 SDK 公网网卡探测，仅在已有原生插件确认权限并读取群组后添加直连网卡；通话开始后授权或建立的群组也能动态加入。持续收集本地地址，初始 SDP 之后出现的私网地址通过加密信令补发，接收端等待对应会话的远端 SDP 就绪后应用；旧会话、重复和非私网地址被过滤。
- 直连是 WebRTC 点对点音频，不通过房主应用转发，底层 Wi-Fi Direct 仍是 Android 的群组拓扑。没有配置 STUN/TURN，仅交换私网 host 候选。
- 直连音频由 DTLS-SRTP 加密；SDP/DTLS 指纹通过既有房间 AES-GCM 信令发送，并绑定 LiveKit 发送者身份。公网继续使用 LiveKit E2EE。
- 每秒检查直连 RTT、增量丢包和抖动。默认 RTT ≤120 ms、丢包 ≤3%、抖动 ≤40 ms，连续 3 次合格才允许切直连；静默时也预热 ICE 质量检查，实际有音频包到达才切换播放；能读取公网 RTT 时，还需比公网低至少 15%。无法读取公网 RTT 时采用上述绝对门限。
- 公网保持订阅和发送，作为热备用，**不会节省公网流量**。接收端先等待旧音轨静音完成，再打开另一条音轨；直连失效、无音频包或策略不允许时回公网。持续约 1.8 秒未完成有效探测也关闭直连。切换可能有短暂音频缺口。
- 接收端按服务端成员策略过滤直连音频；本机发声沿用静音、PTT 与发言权限状态。控制连接恢复中停止使用直连音频。

这是公网在线前提下的融合测试版，不是独立离线房。媒体重连、房间结束、退出或服务端禁用功能时会关闭直连并释放本次建立的 P2P 群组。公网重连后按服务端保留的房间偏好自动恢复，不需要再次打开开关；媒体断连或启动失败后有约 60 秒冷却，再由定期协调自动重试。普通成员先加入时会等待房主群组就绪信号。没有 P2P/公网并发能力的手机可能切断原 Wi-Fi，应用会回到公网重连流程。请先在静止环境测试，不能将本版本视作道路环境验证完成。

## 直连状态与排查（beta.3）

原“直连 0”仅统计实际直连播放中的路数，无法判断有没有连上。现在独立显示 Wi-Fi 建群/等待房主/连接/自动重试阶段，以及已建立的 WebRTC 连接数量。即使两人都没说话，也能显示“直连已连接”；未通过音频质量检查时继续走公网，显示当前选择。附近设备权限缺失、Wi-Fi 关闭、旧系统定位关闭或不支持自动建群时给出具体提示，并定期检查恢复。

所有房间右上角统一一个设置入口。公网房降噪、融合、离线播报及改名放在可滚动面板中，近场房放降噪、日志与诊断；房间名与连接状态保留在页头，融合进度和服务端公告单独显示。

## 动态能力与热配置

`GET /api/v1/info` 新增 `features`，版本为 `schemaVersion: 1`，客户端在进房后和每 30 秒读取。旧服务端没有声明、未知 schema 或不支持房主统一控制时均隐藏融合入口。服务端全局能力与房间开关共同决定是否启用；服务端关闭融合后，正在使用的客户端也会关闭并回退，重新启用后按保留的房间偏好自动恢复。房间偏好通过仅房主可调用的 `PUT /api/v1/rooms/{room}/hybrid-audio` 修改，并持久化到数据库；实时事件与重连快照同步偏好。

服务端设置 `DAWNMESH_CLIENT_FEATURES_FILE=/path/client-features.json` 后，每次 info 请求读取该文件。以临时文件加原子重命名替换配置即可，不需要重启服务或安装 APK。示例：

```json
{
  "schemaVersion": 1,
  "hybridAudio": true,
  "hybridMaxPeers": 4,
  "hybridMaxRttMs": 120,
  "hybridStableSamples": 3,
  "notice": "双线融合正在测试，房主可在房间顶部统一开启"
}
```

范围：maxPeers 1–4，RTT 40–300 ms，stableSamples 3–10，notice 最多 600 UTF-8 字节。配置文件不可读/无效时禁用融合；客户端网络请求失败保留上次有效配置，下一轮重试。未配置路径时使用默认测试参数，房主仍需为房间开启一次，成员自动跟随。

这是数据驱动的已有原生能力开关、参数及公告，不是下载执行任意 Dart/Kotlin 代码。鉴权、入房及管理策略的兼容性修改可以只更新服务端；新原生接口、新音频算法、新页面组件仍需要客户端更新。网页客户端本身可以随服务端更新；本次 Android 功能不通过 WebView 或远程可执行代码提供。

## 安装身份

新安装生成 UUID v4，并另外生成 256 位设备私有凭证，两者保存在安全存储。旧安装保留原 ID，不因升级更换。生成过程跨 store 实例串行，避免并发建房生成不同 ID。网页按浏览器存储生成独立身份；不会按昵称合并不同手机。

服务端保存设备凭证摘要。再次加入同一房间需邀请码与设备凭证校验，复用 memberId、加入顺序、禁言及房主身份，并轮换恢复令牌；房间满员也允许恢复已有身份。旧管理连接收到 session_replaced 后退出，不能继续发控制命令。

旧版未绑定设备凭证的历史成员不会被自动接管。遇到提示时，先从旧会话退出，或让房主移除旧成员再加入；旧房主已不可恢复时，可等待房间到期或重新建房。这是一次性升级边界；不会用可见 UUID 代替认证，也不会直接删除旧成员。

## 依据与验证边界

- [Android 自管理通话音频路由](https://developer.android.com/develop/connectivity/bluetooth/ble-audio/audio-manager)：通信设备选择是异步过程，蓝牙通信与普通媒体输出不同。
- [Android Wi-Fi Direct](https://developer.android.com/develop/connectivity/wifi/wifip2p)：硬件与系统支持决定 P2P 能力；不能假定全部手机都有稳定并发网络。
- [Android 已知群组凭据连接](https://developer.android.com/reference/android/net/wifi/p2p/WifiP2pConfig.Builder)：API 29+ 已知 SSID 和口令时可不指定 MAC，由系统寻找对应群组。
- [WebRTC Android 网络监听](https://webrtc.googlesource.com/src/+/refs/heads/main/sdk/android/api/org/webrtc/NetworkMonitorAutoDetect.java)：Wi-Fi Direct 网络需要额外监听；本实现沿用其 P2P 网络标识与网卡信息格式，但通过应用已有的权限检查读取群组，避免 SDK 内置委托初始化时无权限访问群组。已对锁定的 Android SDK 144.7559.09 验证相关 API。
- [WebRTC 标准](https://www.w3.org/TR/webrtc/)：同一媒体源可以用于不同 sender，接收轨道可单独控制；实际实现以项目锁定的 flutter_webrtc / LiveKit API 为准。
- [Flutter 构建模式](https://docs.flutter.dev/testing/build-modes)：开发期 hot reload 不是生产 APK 任意代码热更新机制。

自动化覆盖房主专属配置权限及持久化、成员自动跟随、房主就绪后才入组、热关闭/重开、空房间关闭聊天页并退出、身份去重和持久化、设备凭证拒绝、旧会话撤销、满房恢复、房主角色/禁言保持、动态配置生效/失效、蓝牙恢复期间的发言状态、质量滞回及音频互斥切换顺序。没有多手机、真实蓝牙耳机、P2P 与蜂窝并发或骑行场景验证，Beta 不承诺无缝/零丢音切换。

## 常亮与房间结束

Wi-Fi、蓝牙、公网房共用通话状态：自动通话和按住对讲期间，应用前台及锁屏通话面板保持屏幕常亮；结束/退房时解除，不主动唤醒已熄灭的屏幕。房间结束时没有有效文本消息则立即返回，打开的聊天页也一并关闭；有文本则保留查看，直到用户退出。图片不算文本消息。网页端同步空房间立即返回与文本保留逻辑。
