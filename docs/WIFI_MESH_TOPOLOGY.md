# 多人 Wi-Fi Direct 与 Mesh（1.1.0-beta.4）

## 本版能做什么

- 纯 Wi-Fi 房由成员连接房主，房主在应用层向其他已认证成员转发语音。已有真实回环 TCP 回归覆盖房主加两位成员的转发。
- 公网融合房在一个 Wi-Fi Direct 群组或已有局域网内，为每对成员建立 WebRTC 通道。Android 群组所有者负责底层组网，房主应用不解码、重发其他人的直连音频。
- 默认每个设备最多连接 4 位同伴，即最多 5 人可形成完整的应用层两两连接。更多成员仍可加入公网房，但不能保证人人都有直连；未连接的成员依赖公网。手机的群组容量、客户端间可达性和并发能力也会限制实际人数。
- 已建立直连在公网断开时继续收发，权限缓存最多保留 30 分钟。自动化模拟房主加两名队友、公网对象消失、静默、PTT、单人离开和权限撤销；没有真实三机射频验证。

## 不等同于扩展距离的 Mesh

[A—B—C] 三台设备中，如果 A 与 C 无法直达，而 B 同时连着两端，本版**没有**跨群组路由、桥接、中继选举、跳数与环路控制。因此不能靠增加中间手机把 Wi-Fi Direct 覆盖距离逐跳延伸，也不保证群组所有者离开后群组继续工作。

Android 官方说明：三台及以上设备组成群组时选出一个 group owner，其他设备加入其群组。这是群组拓扑，不是自动建立的任意多跳网络。[Android Wi-Fi Direct 文档](https://developer.android.com/develop/connectivity/wifi/wifi-direct?hl=en)

研究存在可行的跨群组实验：同时使用 Wi-Fi Direct 与传统 Wi-Fi 接口，以应用层桥接和转发表连接多个群组。2026 年研究在五台 Samsung A10s / Android 11 静态测试台上验证了方案；它没有证明所有 Android 机型、移动场景或公网并发都能稳定工作。[实验论文](https://arxiv.org/abs/2604.07889) 早期方案也需要额外网关协调并权衡时延和功耗。[多群组互联研究](https://arxiv.org/abs/1601.00028)

若继续实现跨群组 Mesh，需单独设计设备能力探测、端到端鉴权路由、序列号去重、TTL、防环、带宽控制及中继失效恢复，并用不同品牌手机实测。不能通过服务端热配置让缺少这些接口和协议的 APK 自动获得该能力。

## 延迟比较

两台手机放在一起时，健康本地链路通常有利于降低传输延迟，但不能保证在拥塞、蓝牙干扰或省电策略下始终更低。Wi-Fi Direct 群组客户端之间也可能经过群组所有者。

旧算法将直连的端到端 ICE RTT 与单个客户端到 SFU 的 RTT 比较，比较口径不同。本版移除这项条件，按直连自身的 RTT、丢包、抖动和连续稳定样本选择。ICE RTT 是连通性/同意检查测得的往返时间，仍不包含完整采集、编解码、缓冲和播放延迟。[WebRTC stats 定义](https://www.w3.org/TR/webrtc-stats/#dom-rtcicecandidatepairstats-currentroundtriptime)
