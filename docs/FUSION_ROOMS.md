# 独立融合房

本文对应 Android 1.1.0 / Server 0.3.0 正式版。请同步更新所有成员的客户端及服务端；本地物理帧仍保持 512 字节，长控制消息使用加密分片，旧客户端无法组装超过单帧的名单。

## 使用方式

首页有 Wi-Fi、蓝牙、公网对讲、融合房四种选择。公网房继续使用 LiveKit；融合房独立使用近场 Opus 加密帧与公网 WebSocket 中继。普通公网房忽略旧服务端的融合开关，配套新服务端也不再允许普通公网房启用旧融合。

融合房最多 16 人，默认按住对讲，可切换自动通话、降噪。创建和本地加入不需要服务器或移动网络，四位码仍通过 SPAKE2 验证。附近成员需要同一 Wi-Fi、热点或 Wi-Fi Direct 链路；可以选择已入房普通成员的本地入口，由其把握手转发到房主。

原来的 6 人上限来自应用代码：成员号分配 1～6、LAN 最多 5 个客户端及融合名单人数校验。本版统一扩大到 16 人（含房主），名单、交接计划和签名状态超过单帧时分片发送，完整组装后才更新本地状态。分片限于名单、交接及融合控制消息，最多 4 KiB，12 秒过期，半份消息不进入业务处理。蓝牙房仍为 6 人。

这不是 Wi-Fi 信道固定人数限制。Android 下层有独立的 AP/P2P GO 最大终端参数与驱动报告能力，不能由 App 的 16 人上限保证每种手机都能组成 16 人的 Wi-Fi Direct 群组。参考 [Android Wi-Fi P2P 群组](https://developer.android.com/reference/android/net/wifi/p2p/WifiP2pGroup) 与 [AOSP AP/P2P 站点容量实现](https://android.googlesource.com/platform/external/wpa_supplicant_8/+/d11f019d62a42a8fc4c4d1f2ec17cf35b0763153/wpa_supplicant/p2p_supplicant.c)。同一局域网/热点或融合房公网成员可以使用应用的 16 人容量。

房间入口把所选服务器、局域网和 Wi-Fi Direct DNS-SD 发现结果按公钥房间 ID 合并。同名但 ID 不同的房间仍分别展示；同房间的多个本地入口保留为备用连接地址，成员数不累加。优先尝试现有局域网连接，再尝试公网及附近直连。未广播房间 ID 的旧版设备单列为“附近设备”，不按设备名猜测其归属。DNS-SD 只广播公开的房间 ID 和名称，入房仍需邀请码验证。

只有房主时，本地没有队友连接属于正常状态；建立 Wi-Fi Direct 群组只表示附近入口就绪，不代表连接了路由器或正在与队友协商语音。公网状态以融合房服务器连接为准：旧服务端未提供接口时明确提示更新服务端，访问凭证错误、超时及中继升级失败分别提示。手机能上网不代表所选服务器已支持融合房。

任一成员配置了服务器并可联网后，自动上传房主签名的名单，建立公网桥接。房主本人可以始终离线。远程成员从同一服务器的融合房列表加入，验证消息通过已有网关转发到房主。多位成员同时联网无需选举，也不需要各自打开开关。已验证的房间通道会交换 Wi-Fi Direct 就绪信息，附近的公网成员可自动尝试建立本地连接。

公网中断不会关掉本地房间，也不限制已经连通的离线通话时长。已入房成员交换加密的本地 IP/端口，成员按成员号组成邻接环路，每对邻接成员由较小成员号发起连接，避免全互连；保留已有房主/引导连接作为额外路径；其他成员可以经这些连接转发密文，不要求经过房主。

房主 12 秒没有数据不再触发重新验证邀请码。只要任一已验证成员仍有合法数据，成员间继续通话；全部队友都连续 12 秒无数据时才开始 30 分钟恢复期，保留原成员号、名单和加密密钥，只重建传输连接。收到已知成员的合法密封帧后恢复通话，不恢复按住对讲的按下状态。30 分钟仍未恢复才断开并停止录音。解散和退出沿用原来的聊天保留规则，无文本消息时直接离开。

## 语音质量

房间右上角“房间设置”提供与公网房一致的清晰、平衡、省流档位。修改只调整本机发送的 Opus 码率，不重启录音、不切换通话模式。

| 档位 | Wi-Fi / 以太网 | 移动网络或网络未知 |
| --- | --- | --- |
| 清晰 | 32 kbps | 20 kbps |
| 平衡 | 24 kbps | 16 kbps |
| 省流 | 16 kbps | 12 kbps |

未手动选择时，Wi-Fi 默认清晰，移动网络默认省流；手动选择后，本次房间保留所选档位。数值为语音编码码率，不包含传输开销；本地与公网同时发送仍会使用公网流量。

## 数据与身份

- 每次建房生成 Ed25519 密钥；公钥即房间 ID，只有创建者持有签名私钥。
- 四位码只用于 PAKE 验证，不直接作为音频加密密钥。握手完成后取得随机房间密钥；Opus、聊天与融合控制消息在本地和公网使用相同的密封帧。
- 本机安全存储的安装凭证与房间 ID 经 HMAC 派生 16 字节入房身份。同一安装重连可取回原成员号；服务端名单只接收该房间内的身份摘要，不上传安装凭证。
- 房间中继能力密钥只在已验证的加密通道中下发。服务器访问凭证仍由各手机自行安全保存，不转发给其他成员。
- 房主定期签名成员快照，包括昵称、房内身份、成员号和递增版本。任一网关可上传，服务端验证签名、有效期、身份唯一性与单调版本，拒绝改写或旧快照覆盖。服务器重启后可由在线成员上传仍在有效期内的签名快照恢复；房主长期不可达且快照已过期时，旧快照不能重建被清空的服务端记录。
- 离线创建者通过签名的解散状态通知本地和远程成员，网关上传后服务端保留解散标记。服务端记录在最后一次有效快照或已验证成员数据之后保留 30 分钟；活跃成员的数据只续期记录，不修改房主签名版本。已验证成员可以凭原房间能力恢复中继，未入房者仍要求 90 秒内的房主快照。解散标记和过期记录不能靠旧凭证重新打开。

## 多路径与实际边界

融合房对同一个加密包同时使用已有本地连接和公网备用通道，接收者采用先到达的一份，以完整密文摘要做有界去重。没有两个独立录音轨道，也不会将同一音频再次解码或混音。多个网关及本地环路同样去重。公网备用仍消耗流量；省流档只降低编码码率，不代表自动停止公网副本，也不保证最短路径最优。

这是应用层转发，不是 802.11s Mesh。Android Wi-Fi Direct 仍受单群组、硬件并发连接及系统权限限制，不能把三台手机摆成任意距离的无线多跳网络。已存在的 IP 连接可以互相转发，无法凭软件跨越不存在的无线链路。如果房主同时是唯一 Wi-Fi Direct 群组所有者，离开后导致整个无线群组消失，其他成员仍需同一 Wi-Fi、热点或公网等可用路径；本轮没有实现无线群组所有者自动迁移。离线入房也需要一条最终可达逻辑房主的路径；没有实现离线房主永久退出后的分区选举。

房间列表与成员信息只在所选自部署服务器间同步，不跨不同服务器自动互联。服务端只中继密文，不参与语音解密；融合房暂不提供公网房的管理员收听、房主移交和 25 人规模。

本机真实套接字测试包括 16 人 Wi-Fi 与融合房完整长名单、满房重连、17 人拒绝、16 人签名状态和语音去重，并覆盖离线建房、经成员验证加入、错误码拒绝、三角环路去重、PTT 重连、成员自动建立直连后房主消失仍通话、全部队友失联后的 30 分钟恢复、音质切换保持 PTT 关闭、离线房主经双网关连接 Go 服务端、远程加入、一个网关退出后继续通话和解散。尚未进行多台 Android 手机上的 Wi-Fi Direct 射频、系统休眠及道路语音实测。

## 协议与部署

- 本地发现：UDP 8992，`DAWN_MESH_FUSION_V1`；与 Wi-Fi 房发现隔离。
- 本地加密帧入口：TCP/WebSocket 8991，`/fusion/{roomId}`。
- 公网列表：`GET /api/v1/fusion/rooms`。
- 网关同步：`PUT /api/v1/fusion/rooms/{roomId}`，上传签名 manifest/state，`X-Fusion-Key` 验证房间能力。
- 公网中继：`GET /api/v1/fusion/rooms/{roomId}/relay` WebSocket。继承服务器 Authorization 访问控制；未入房连接只短暂承载受限握手，20 秒内必须完成验证并提交房间能力。
- HTTP 反向代理需允许 `/api/v1/fusion/` 下 WebSocket 升级；使用现有服务器域名和 TLS，不另开公网端口。

16 人容量与长控制消息组装需要全体成员更新 Android 1.1.0；融合房需要 Server 0.3.0 接受 16 人签名名单并采用配套中继限流参数。已有热配置仍可更新通知等已实现能力，不能向旧 APK 注入新协议或新界面。
