# 公网融合房重连后未按键发声排查

状态：修复纳入 1.1.0-beta.5 / versionCode 47；1.1.0-beta.4 不包含这些防护。需要更新 APK，服务端热配置不能补上本地音轨控制逻辑。

用户确认开启双线融合，房主断线恢复后确实能听到未按键成员的声音。未连接对应手机、没有现场日志，因此尚不能确定当次触发顺序。

## 已确认的代码缺口

- 房间会话中的 PTT、静音和发言权限判断存在，但 beta.4 的 IntercomAudioTrack 沿用 LiveKit 的 enable/unmute。锁定的 LiveKit 2.12.0 在收到 SignalRemoteMuteTrackEvent（解除静音）时直接调用 publication.unmute，绕过会话的 PTT 判断。beta.4 并没有完整封住底层开麦入口。
- SDK 的 mute 在缓存 muted 已为 true 时直接返回；如果底层采集音轨在重建后处于 enabled 状态，重复调用 mute 不能保证将其关闭。
- 原先松手的采集操作排在麦克风队列中，可能等待正在进行的采集重建完成；SDK 的 restartTrack 也会先将新音轨挂到发送器，然后更新引用，存在新音轨启用早于重新检查 PTT 的窗口。

以上是可从源码确认、用模拟音轨验证的路径，不等同于已重现用户手机上的完整故障。

## 补丁

- 音轨持有本机会话的即时发言判断，enable/unmute 和重新启动都受 PTT、自动通话、静音、权限及退房状态约束。SDK 不能自行授权开麦。
- 静音操作始终关闭实际轨道，即使 SDK 的 muted 标记已经为 true。
- 松手时先立即关闭实际音轨，再执行异步队列；直连仍按最新本机状态决定是否挂载发送源。
- 重建采集时，先关闭新轨道并校验本机状态，再挂载到发送器。公网发送器不可用时保留直连采集。
- 记录被拦截的不合规开麦请求，便于后续真机排查，不记录语音内容。

## 验证

Flutter analyze 无问题，完整 271 项回归通过。未做对应手机的真机复现。

快速松手再按下时也会同步实际轨道与 SDK 静音标记，避免防护导致后续正常按键无声。

新增测试覆盖：SDK 直接解除静音/enable、已静音标记与实际轨道不一致、重建过程中松开 PTT、房主快照及权限恢复，以及实际 HybridAudio 协调器与受保护音轨组合的房主直连重新协商。组合测试确认旧发言状态尚未清理时，松开的本机状态仍能阻止给新直连挂载麦克风；再次主动按下后正常发送。

需要真机复测：双方更新含本补丁的 APK 后，成员先按下再松开，房主分别关闭移动数据、恢复网络及退出后重新加入，确认未按键成员始终没有语音传出，同时正常按键和自动通话仍可用。
