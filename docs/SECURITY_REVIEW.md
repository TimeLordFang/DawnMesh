# Android 源码安全审查（2026-09-07）

## 结论和范围

在检查的 Android Flutter 主线、Dart 会话/传输/更新逻辑、原生音频/BLE/Wi-Fi 插件、C++ 核心和构建配置中，**未发现明确的恶意后门证据**（例如隐蔽上传录音、命令执行、动态下载执行代码、固定远程控制端）。这不是“已证明没有后门”：未取得你手机上的 APK，未做 APK 与源码一致性验证、全依赖源码/二进制逆向、动态抓包和模糊测试，也未全面审计其他平台。旧根目录 app/ 仅做相关构建、安全和蓝牙路径抽查。

原版不能按“默认端到端加密、安全匿名通话”理解。DawnMesh 已将六位数字 PAKE 入房验证和随机组密钥加密接入全部应用入口；这修复默认明文和无邀请码入房，但并不提供每位成员的独立身份认证。

以下路径均相对于原 sunsetripple 仓库；可对照同路径的 DawnMesh 修复。

## 发现

| 风险 | 证据与影响 | DawnMesh 状态 |

| 高：默认应用层明文 | `lib/core/session/room_session.dart::secureCodec` 默认为 null；首页没有握手或赋值；`LanTransport` 直接 Frame.encode；BLE 用 `listenUsingInsecureL2capChannel/createInsecureL2capChannel`。局域网可监听语音/聊天/控制数据；BLE 不能假定有认证加密。 | dev.3 改为六位数字 PAKE 验证、独立随机 256 位组密钥。握手点与确认包公开传输，验证完成后的语音、聊天和成员控制均密封，无明文兼容降级。 |

## 联网、权限与数据路径

- 主线外网 HTTP 入口是用户在关于页面触发的 GitHub Releases 更新检查；本次未发现偷偷向分析/广告服务器上报的主线代码。DawnMesh 移除此入口的联网逻辑。
- `INTERNET` 同时用于本地 TCP/UDP，不能因应用“离线”就移除此权限，也不能仅凭该权限认定有后门。
- 录音由进房后的音频初始化开启，PTT 松手时 Dart 阻止语音帧发送；麦克风采集本身可仍保持打开。前台服务显示通知，START_NOT_STICKY，不见开机自启动/隐藏录音上传逻辑。后台/快速进退房仍需真机验证。
- Manifest 对外导出的主入口是 Launcher Activity；通话 Service 不导出。Flutter 主线不申请联系人、短信、通话记录、无障碍或安装 APK 的权限。
- 语音和聊天主要在内存处理，没有发现主线主动保存录音文件；日志、系统备份、进程内存及参与者自行录音意味着不能承诺绝对“无痕”。
- 旧 Kotlin `app/` 有 Google Nearby 依赖及另一套更新实现，不能把它的依赖/安全行为套到当前 Flutter APK；DawnMesh 不包含这套工程。

## dev.3 六位邀请码与加密边界

- 邀请码是均匀随机 `000000`–`999999`，约 20 位熵，便于离线口述。**不直接对短码做 SHA-256 后当作 AES 密钥**。原 dev.2 的 22 位密钥派生协议已替换，不兼容旧包。
- 入房采用基于 [RFC 9382](https://www.rfc-editor.org/rfc/rfc9382.html) 的 SPAKE2 P256/SHA256/HKDF/HMAC 运算；短码通过 scrypt（N=16384、r=8、p=1、40 字节输出）生成标量。在独立 isolate 做 KDF，避免阻塞界面。双向确认后，经 PAKE 派生的包装密钥加密下发每次建房独立生成的 32 字节房间密钥。相同数字的两个房间也不共享语音密钥。
- 曲线接收值检查 SEC1 编码、坐标范围、曲线方程及非无穷点；每次握手使用新的随机标量。客户端会话令牌绑定握手身份和密钥下发；过期/错码/未确认握手不能取得组密钥。标准附录 B 的点、共享密钥、双方确认值在测试中匹配。
- 房主最多同时保留 5 次待确认握手，12 秒过期；每分钟最多受理 10 次挑战，一个房间生命周期最多 120 次，降低在线猜码速率。达到限制后须等待或重新建房；这是可用性与防猜码的权衡。物理连接占位和恶意干扰仍可能造成拒绝服务。
- **实现审计限制**：使用 PointyCastle 大整数/椭圆曲线运算，它不是经过认证的常数时间 PAKE 原生实现。本次通过标准向量与协议回归，不代表完成侧信道、实现级密码学或第三方独立安全审计。不能据此承诺短码具备 128 位密码强度或完全抵御攻击。后续应替换/复核为受审计的常数时间密码库。
- 会话 AES-GCM 仍使用 8 字节随机发送器前缀 + 4 字节计数器 nonce，1024 帧滑动重放窗口、最多 128 个发送器前缀，认证失败不修改重放状态。客户端收到匹配其本次会话令牌的加密 admission 后才接受名单。
- 房内仍是一把组密钥：合法成员可解密内容，恶意持码成员可能冒名；退出不自动换钥。需要撤销成员时，应结束房间再建房。PAKE 临时交换避免把短码本身作为录制语音的解密密钥，但完整多成员会话的前向保密、退群后保密与成员独立认证尚未完成。
- 房间名、设备地址、人数、外层 senderId/序号及流量时序公开。参与者可录音/截屏；邀请码每次显示 10 秒后隐藏、切后台立即隐藏，但仍可能被旁人看到。没有匿名性或“无痕”保证。
- 为避免 Android 10+ Wi-Fi Direct 房主侧的旧式 WPS 确认，dev.5 会从 6 位邀请码确定性派生临时 P2P SSID 和 WPA 口令。它不替代应用层 PAKE/AES-GCM，但会把短码暴露给 Wi-Fi 口令的离线穷举风险；附近攻击者可枚举约一百万种数字。重视保密时优先使用普通可信局域网或蓝牙房，并在会后重建房间更换邀请码。Android 8/9 不支持带已知凭据创建 P2P 群组，仍可能显示系统确认。

## 锁屏与自动通话

- 自动通话按本地响度门限触发，静音仍持续采集以判断是否有声音，但不发送静音帧；关闭麦克风/退房停止发送。硬件麦克风指示与常驻通话通知保留。
- 新增 `WAKE_LOCK`，仅活动通话持有 CPU 唤醒租约，前台服务销毁时释放；Wi-Fi 房持有网络锁。没有开机启动、自动录音或云端语音识别。
- `LockScreenTalkActivity` 不导出，经应用私有不可变 PendingIntent 打开。只显示模式、按住对讲与静音控制；不调用解除系统锁屏 API，不展示邀请码、成员名或聊天。按键取消/面板 onPause/主界面失去焦点时释放 PTT。
- 锁屏通知会透露应用正在通话，但不含房间秘密。通知权限和厂商后台策略可能影响面板显示与收发，仍需按复测表在两台 Android 16 手机上确认。

## 后续优先级

1. 每连接独立认证、成员号与认证链路绑定、入站验证后中继、房主端未认证连接期限、退出换钥。
2. TCP 背压和全链路速率限制；如果恢复 UDP 语音，必须加入 AEAD 与认证端点绑定。
3. 依赖清单/漏洞扫描、最终 APK 抓包、两品牌真机和多成员压力测试。本次源码审查不等于完成依赖二进制审计。

本次验证的是代码、协议测试和 APK 构建，不将未执行的手机测试或未解决的组内信任问题描述为已完成。
