# 安全模型与已知边界

整理日期：2026-10-27，适用于本次待发布的 v3 近场协议；发布前仍需设备验收。本文合并早期源码审查和后续修复状态；它是项目实现说明，不代表完成独立密码学审计、全依赖二进制审计或真机抓包验证。

## 房型与信任模型

| 房型 | 入房与内容保护 | 主要边界 |
| --- | --- | --- |
| Wi-Fi / 蓝牙 | 四位数字邀请码经 SPAKE2 验证后分发随机 256 位房间密钥；应用数据使用 AES-GCM 密封帧 | v3 每帧独立成员签名；成员仍可读取共享给全房的内容 |
| 融合 | 沿用近场 PAKE/密封帧；房主以 Ed25519 签署名单，网关同步，公网只转发密文 | 新成员认证仍需可达逻辑房主；v3 对语音和控制都验证独立成员签名 |
| 公网 | 协议 2 使用每房随机盐、scrypt 派生入房凭据与封装密钥；LiveKit 媒体 E2EE，聊天使用用途隔离的 AES-GCM 密钥 | 服务器保存的凭据摘要及密钥信封仍允许泄露后离线猜四位码 |

当前入口只接受四位数字，旧六位兼容已在 1.0.3 移除。四位码仅有 10,000 种组合，适合临时可信小组，不等于高熵密码。Wi-Fi Direct 的 SSID/WPA 凭据由邀请码派生时仍有离线枚举风险，外层口令长度不能增加原始邀请码的熵。

近场 PAKE 不直接把短码当作媒体密钥；每房生成独立随机组密钥。握手校验曲线点、确认值和客户端随机令牌；完成匹配 admission 前不接受成员名单。使用 PointyCastle 的实现未完成常数时间、侧信道或第三方独立审计。

## 已实施的防护

- 加密失败停止发送，加密会话拒绝未密封数据和嵌套伪握手；正式 Wi-Fi 加密房使用 TCP 承载密封帧，旧 UDP 音频路径不是生产加密通路。发现广播仍公开。
- AES-GCM nonce 为 8 字节随机发送前缀与 4 字节计数器；1024 帧重放窗口，最多 128 个前缀，认证失败不修改窗口。同密钥重连保留窗口和发送计数，换密钥才创建新状态。
- 近场限制待确认握手、超时和受理速率，保留每房 120 次失败/放弃预算；成功握手不再消耗该预算。容量相关并发值由实现决定，不能继续套用旧版固定 6 人的参数。
- 蓝牙房主先认证解密，再按语音/控制类型分配本机发送队列策略，线上仍转发原密文。队列、超时和语音过期清理降低慢链路影响，不表示已解决全部资源耗尽。
- 公网使用安装私有凭证和轮换会话令牌恢复身份；公开 UUID 不能单独授权接管。房主权限在服务端核验，迟到的旧连接关闭事件不能覆盖新连接。
- 公网及近场的 PTT、静音和权限约束在恢复时保留；前台服务启动失败、失焦和退房不能导致异步重新开麦。语音状态恢复不自动恢复按键按下状态。
- 发布签名不回退 debug；版本声明与应用更新日志有一致性检查。Android 备份和设备迁移规则排除身份、凭据与房间密钥。

相关修复见 [1.1.2](RELEASE_1.1.2.md)、[1.1.3](RELEASE_1.1.3.md)；融合签名、新鲜度、去重和重启行为见 [融合房](FUSION_ROOMS.md)。

## 仍存在的边界

- **组内信任**：v3 持有组密钥不足以伪造其他成员的签名；房主负责认证并签署成员公钥映射。合法成员仍可读取、转录、转发房间内容，恶意房主可能不执行移除或向第三方泄露密钥。历史同步由房主背书，不等同于保存了每条历史消息的原作者签名。
- **密钥生命周期**：成员退出/失联清理和房主交接会换 epoch，随机新组密钥分别封装给保留成员；无法收到换钥通知的成员需要恢复 PAKE。固定身份密钥与静态 X25519 封装不构成完整多成员前向保密，事后泄露设备身份密钥仍可能影响录制流量。不得用普通 TTL/LRU 清除仍在使用的密钥对应的防重放记录。
- **可用性**：未认证物理连接占位、失败预算耗尽、TCP 背压和全链路限流仍需设计及压力验证。重建房间恢复可用性不等于抵御主动干扰。
- **公网访问**：HTTPS 和部署访问令牌保护传输/入口，不能提高四位邀请码本身的熵。管理员收听需要建房时明确授权；授权房间会向服务器提供可托管的媒体密钥，不能视为对管理员保密。
- **元数据与日志**：房间名、设备地址、人数、外层标识和流量时序可能公开。日志和诊断分享前仍需检查昵称、地址及上下文；不公开邀请码、服务器凭证或签名材料。
- **用户内容**：普通语音和聊天在会话内存中；语音留言默认关闭，启用后按键片段最多保留 15 秒并可补送。离线转交另行显式启用，持久化加密保存，正文仅收件人解密，但转交者可见公钥路由身份、大小和到期时间。其他参与者可以录音、截屏，不能承诺匿名或无痕。

## 权限、联网与验证

`INTERNET` 用于本地 TCP/UDP 以及用户选择的公网服务，不能仅凭权限判断数据上传。普通公网房使用配置的服务器及媒体服务，融合房可由已联网成员桥接；应结合所选房型理解流量。

Android 通话前台服务、通知、锁屏控件和活动通话唤醒锁有明确生命周期，后台及厂商系统行为仍需设备验收。诊断不是全系统 Logcat 访问；源码检查也不能证明手机上某个 APK 与仓库一致。

自动化与产物检查见 [验证基线](VALIDATION.md)。后续重点为独立密码审计、资源与容量限制、依赖与最终安装包验证，以及多品牌真机测试，集中跟踪于 [设备验收](MANUAL_ACCEPTANCE.md)。上游来源与许可保留在 [UPSTREAM](UPSTREAM.md)。


## 本次新增协议约束

- v3 安全房要求所有参与者使用升级后的客户端，不协商降级为只持有共享密钥的旧协议；公网 LiveKit 房的协议保持原有路径。
- PAKE 双方对当次握手和完整公钥组合提供签名持钥证明，已有签名身份不能被替换为另一把协商公钥。独立 Ed25519/X25519 身份来自专用安全存储种子，不由服务器知道的设备凭证推导。安全号码覆盖两把公钥；核对需可信的带外渠道，显示号码不等于已完成核对。
- 签名覆盖房间上下文、epoch、内层完整帧；先验证签名再提交重放窗口。消息 ID 包含独立身份命名空间，三位设备编号碰撞不授予撤回权限。
- 融合转发预算最多 8 跳，跳数是可变路由元数据；它限制守规节点的循环流量，不是抵抗恶意节点重置计数的密码凭据。队列有界，过期音频可丢弃，控制拥塞关闭该链路。
- 离线转交使用临时 X25519 密钥和收件人持久身份密钥派生 AES-GCM 密钥，发送者 Ed25519 签署完整密文和路由头。并不提供抵抗收件人私钥事后泄露的前向保密。
- 离线消息与签名撤回共用 64 条/256 KiB 本机配额，最长 24 小时；精确 128 位摘要分页对账，没有布隆过滤器假阳性导致的静默丢失。诚实设备每条最多 8 次发送、4 跳，不能宣称全网副本数量严格受控。
- 撤回通过原作者签名通知合作节点，不能远程抹去已读内容或恶意持有的副本。后台未运行时无法主动清理磁盘，到下次启动或参与交换时清除到期记录。关闭转交保留本机数据，清空功能另行删除联系人和队列。
- GATT 备用链路仅承载文字与必要控制；图片、语音留言和实时音频仍要求较快链路。原生队列、分片和超时有界，但不同手机、后台限制及并发吞吐尚待真机验收。
