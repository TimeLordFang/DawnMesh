# Android 蓝牙搜房、音频与恢复排查

适用于当前 DawnMesh Flutter 正式版。先记录两端 APK 版本、手机/耳机型号和系统构建号；旧 SunsetRipple Kotlin/RFCOMM 客户端不能视为 BLE L2CAP 兼容客户端。跨端房名/GATT 修复见 [1.1.4](CHANGELOG.md) 和 [1.1.5](CHANGELOG.md)。

## 分层排查

1. 确认应用内已启动蓝牙扫描，房主广播成功；广播失败不能只凭进入房间页面认定建房成功。
2. 检查麦克风、附近设备和对应系统版本要求的定位权限/开关。Manifest 声明不代表已授予权限。API 版本与应用 targetSdk 是不同条件，当前构建值见项目 README。
3. BLE 房间在应用内发现，不依赖系统经典蓝牙“配对新设备”列表。不要快速反复停启扫描；先保持前台、近距离验证，再排查省电和后台限制。
4. 列表为空检查扫描与广播解析；列表有而连接失败检查地址、动态 PSM、L2CAP 和超时；连上没声音再检查采集、PTT、音频路由。
5. 主广播携带 PSM/人数，扫描响应与 GATT 补全名称。中文/emoji 长名称不应被较短的后续广播覆盖；重建房间或蓝牙开关后应读取最新 PSM。

不能仅凭 Android 版本或“蓝牙 5.x”认定设备支持广播和稳定多人 L2CAP；具体 ROM、硬件与权限需要实际验证。

## 设备复测

所有设备安装同一正式版，允许蓝牙/附近设备与麦克风，先保持前台、相距 1–2 米，再逐步增加设备和距离。当前邀请码为四位数字，蓝牙房最多 6 人。

| 场景 | 应检查的结果 |
| --- | --- |
| 建房后查看邀请码 | 聊天室信息下方显示 4 位数字，10 秒后隐藏；眼睛可切换，每次显示重新计时；切后台立即隐藏 |
| 锁屏面板布局与触控 | 文字清晰、系统栏不遮挡，横屏/大字体可滚动操作；按住后滑出圆环停止，滑回不恢复发送；多指不误开麦 |
| 小米创建，一加选择“蓝牙对讲”并扫描 | 10 秒内看到房间，点击加入并输入房主提供的 4 位数字邀请码；双方名单出现第二人 |
| 扫描中文蓝牙房名 | 房名前不再出现 PSM/人数控制字节造成的两个乱码字符，emoji 或中文结尾不会被截成半个字符 |
| 一加创建，小米扫描 | 反向同样成功 |
| 两端分别按住说话并松开 | 对端能听到；松开后不再发送本机语音 |
| 蓝牙房切换“自动通话” | 不按键说话能传到对端，安静时不持续发送；切回按住模式后不按键不发送 |
| 两台采用不同发言模式 | 按住端与自动端均可正常互听 |
| 自动通话锁屏 1/10/30 分钟 | 继续互听；从安静到说话能够自动开始发送 |
| 按住模式锁屏 | 点击常驻通知打开锁屏面板；按住能发送、松开/再次熄屏停止发送，接收继续 |
| 锁屏面板切换模式、静音 | 主界面恢复时显示同一状态；静音时所有发言入口均不能发送 |
| 快速退房/启动中退房 | 麦克风不复活，前台通知消失，CPU/Wi-Fi 锁释放 |
| 建房前关闭蓝牙 / 拒绝权限 | 明确错误，不能进入一个虚假的房间；恢复后可重试 |
| 输入错误邀请码 | 8 秒内提示验证失败，不开麦、不进入房间 |
| 房主离开再创建 | 旧房消失，重新扫描拿到新 PSM；使用新的邀请码再次加入 |
| 快速点击建房/加入 | 只启动一次操作，不产生多个连接/重复房间 |
| 加入/离开人数变化 | 房间人数更新，广播回调不出现 Reply already submitted |
| 入房后切后台 30 秒、熄屏 1 分钟 | 记录声音/连接变化；若仅后台失败再检查厂商电池策略 |
| 3–6 台、远距离/干扰、连续 10 次进退房 | 记录断连、卡顿、资源泄漏；这是后续压力测试 |
| Redmi K50 Ultra 三机近距离双向通话 | 分别测试按住和自动模式至少 2 分钟；关注日志中的 `音频缓冲`、`编码超过20ms`、`maxTx/maxRx`，记录是否仍有连续断音 |


对每台手机分别保存只读诊断（不要把完整日志公开，可能含设备地址/昵称）：

```sh
adb devices -l
adb -s SERIAL shell getprop ro.product.model
adb -s SERIAL shell getprop ro.build.version.release
adb -s SERIAL shell getprop ro.build.display.id
adb -s SERIAL shell dumpsys package dev.dawnmesh.intercom
adb -s SERIAL logcat -v time DawnBle:I DawnMain:I DawnAudio:I flutter:I '*:S'
```

顺序判断：没出现“开始扫描蓝牙房” → 扫描/权限入口；房主没“BLE 广播已开启” → 广播/权限/硬件；双方都有但列表为空 → 扫描结果/广播解析；列表有而连接失败 → PSM、L2CAP、超时；连接成功没声音 → 麦克风、PTT、音频路由，与搜房分开定位。



## 耳机共存与指标

手机间 BLE L2CAP 数据与耳机通话共用蓝牙控制器和空口，不能直接把双向卡顿归因于芯片性能或硬件损坏。戴蓝牙耳机时可对照 Wi-Fi 房；麦克风来源和实际 HFP/LE Audio 路由需记录。音频档位和参数以当前界面为准，不沿用旧开发版固定码率/缓冲值。

每组 A/B 测试只改一个参数，保存后等待至少 15 秒再记录，并注明手机、耳机、距离和参数：

- `captureGap` 异常、Socket 平稳：优先排查采集路由与系统调度。
- `write/flush` 与 `rxGap` 同时出现尖峰：检查控制器共存和链路调度。
- `queueAge` 持续增加：检查待发积压。
- `rebuffer` 增长但 `trackUnderruns` 为零：优先排查数据到达；后者增长说明播放调度也有影响。

耳机断开再恢复后，检查路由与采集重建；未按住 PTT、静音或被禁麦时不能发出语音。弱网/房主恢复组合步骤见 [验收表](VALIDATION.md)。日志指标用于定位，不替代实际听感和端到端延迟测量。
