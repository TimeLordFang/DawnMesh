# DawnMesh 1.2.0

Android 与 iOS 统一为 **1.2.0 / 构建 61**，图标统一选用“曙光声波”：深蓝背景、暖色太阳与三条声波。安卓桌面/自适应/主题图标、通话通知、商店图标，以及 iOS 各图标外观、启动画面和两端关于页使用同一品牌资源。

## 通信与恢复

- 融合链路采用有界发送队列，过期实时语音不继续排队；慢链路拥塞不会无限占用内存。新增链路队列、语音丢弃和发送字节诊断。
- 文字使用确认、有限重试和紧凑的精确摘要分页补齐。分区恢复后去重，撤回不因延迟消息或历史同步复活；送达状态不把未知接收者算作已确认。
- v3 近场房间使用独立 Ed25519/X25519 成员身份，验证语音和控制帧签名；退出、失联清理和房主交接轮换 epoch 与组密钥。安全号码可在房间设置中核对，三位设备编号碰撞不会授予他人消息的撤回权限。
- 蓝牙 L2CAP 无法连接时尝试 GATT 小消息备用，明确显示“仅文字”，不打开实时麦克风或发送图片/语音附件。连接诊断提供下次加入时使用备用通道的验收开关。

## 可选功能

- **语音留言默认关闭。** 开启后将自己的按键通话最多保留 15 秒，松开后可补送；实时与补送合为一条留言。可取消、撤回和主动播放，实时通话到来时停止留言播放。
- **离线转交默认关闭。** 核对并保存联系人后，可密封短消息给离线的指定收件人，由同样开启转交的房间成员分时携带。最多 64 条/256 KiB、24 小时、4 跳、本机每条 8 次发送。精确对账、持久化去重和签名撤回不等于保证送达或远程擦除已读内容；转交者可见路由身份等元数据。
- **Wi-Fi Aware 为主动启用的加速能力。** 在已建立的融合房中通过系统标准配对添加本地通道，失败时保留现有 LAN/云端/原生点对点路径。Android 使用 API 37 的配对数据通道接口并检测硬件配对支持和当前可用性；iOS 需要 iOS 26+、兼容硬件及 Publish/Subscribe 签名权限。设备间实际无线互通、功耗和后台表现仍需实测；旧系统继续使用原连接。

上述队列、精确对账、移动信使及分层传输思路受到 [Bitchat](https://github.com/permissionlesstech/bitchat) 的技术启发，结合 DawnMesh 实时语音场景独立实现；没有复制其 Android GPL 源码。本次不提供与 Bitchat 网络或协议互通。

## 升级与验收

- **近场房间要求全体升级到 1.2.0。** v3 成员认证与 epoch 不降级到旧共享密钥协议；公网 LiveKit 房沿用现有通路。
- Android Release 同时提供签名 APK、Google Play AAB 与 SHA-256。AAB 供 Play 上传，不能直接点开安装；Play App Signing 还需正确配置与已有安装的签名兼容。
- iOS Release 提供未签名 `.app.zip`，用于检查和自行签名，不可当作可直接安装的 IPA。使用 Wi-Fi Aware 时应在开发者账户/描述文件中启用相应能力。
- 五台已知设备的完整步骤见 [手动验收](MANUAL_ACCEPTANCE.md)。目前没有连接真机，不宣称射频、跨平台配对或锁屏通话已经验收。
- 密码学实现边界、历史同步信任与元数据说明见 [安全模型](SECURITY_REVIEW.md)。完整调研报告保留本地，不纳入本次 Git 提交。
